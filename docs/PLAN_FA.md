# پلن ساخت و وضعیت پیاده‌سازی

این سند پلن ساخت ربات (بر اساس PRD) و وضعیت واقعی هر بخش را نشان می‌دهد. برچسب «آماده» فقط برای چیزی آمده که اجرا و تست شده است.

## تصمیم‌های گرفته‌شده با مالک پروژه

| موضوع | تصمیم |
|---|---|
| واحد پول | **همه‌جا ریال.** سقف ۳٬۵۰۰٬۰۰۰ ریال. ستون‌ها `*_rial`. |
| ورود مبلغ بدون واحد | ربات **می‌پرسد** (ریال یا تومان) و معادل ریالی را برای تأیید نشان می‌دهد. |
| ثبت کارکنان | **درخواست عضویت در ربات + تأیید ادمین.** ثبت دستی در شیت هم کار می‌کند. |
| هوش مصنوعی | **ماژول Gemini ساخته شده ولی پیش‌فرض خاموش است.** فقط با تأیید سازمان و کاربر روشن می‌شود. |
| هزینه ارسال/بسته‌بندی/مالیات | **جزو مبلغ قابل بازپرداخت است** (مبلغ نهایی پرداختی). با Settings قابل تغییر است و ادمین می‌تواند با ذکر دلیل کسر کند. |

## معماری

`Telegram Bot API → Webhook → Google Apps Script Web App → Google Sheets + Google Drive (+ Gemini اختیاری)`

اصول طراحی:

- **موتور مالی قطعی و جدا** (`Finance.gs`): `allowed_i = min(cost_i, max(0, cap − approved_i_today))`. کل مبلغ مجاز به پرداخت‌کننده تعلق می‌گیرد. محاسبات با عدد صحیح انجام می‌شوند و تقسیم، باقی‌مانده را توزیع می‌کند.
- **فرم مبتنی بر وضعیت:** مرحلهٔ بعد همیشه «اولین مرحلهٔ ناتمام» است. بازگشت، اصلاح و ادامهٔ درخواست نیمه‌کاره همه از یک منطق پیروی می‌کنند.
- **همزمانی:** یک قفل سراسری روی هر update. تأیید اتمیک با بررسی دوبارهٔ سقف و «مبلغ مورد انتظار»، و حذف تکراری‌ها با `update_id`.
- **حریم خصوصی:** فقط چت خصوصی، Drive خصوصی، دسترسی با Telegram ID و پنهان‌سازی اسرار در لاگ.

## فازها

### فاز A — هسته بدون AI (✅ ساخته و تست شد)

1. ✅ پروژه Apps Script، شیت‌ها و پوشه‌های Drive (`setup` تکرارپذیر)
2. ✅ BotFather، توکن در Script Properties (راهنما در README)
3. ✅ Webhook با secret مسیر و حالت پشتیبان Polling
4. ✅ allowlist کارکنان، درخواست عضویت، نقش‌ها
5. ✅ فرم آنلاین/حضوری × بانکی/اعتباری/ترکیبی، بازگشت، لغو، ادامه
6. ✅ دو مدرک اجباری (چند تصویر برای هر مدرک، کپشن، حذف و ارسال دوباره)
7. ✅ افراد از فهرست یا متن (رفع ابهام نام مشابه)، پرداخت‌کننده، مبلغ با واحد، سهم مساوی یا جداگانه
8. ✅ موتور سقف روزانه مشترک بین سفارش‌ها و تخصیص به پرداخت‌کننده
9. ✅ تأیید/رد/اصلاح/اصلاح مبلغ/پرداخت/لغو تأیید + Audit Log
10. ✅ گزارش Excel (۶ شیت) و PDF فارسی و ارسال خصوصی

### فاز B — هوشمند رایگانِ مشروط (✅ ساخته شد، ⚠️ مشروط به محیط واقعی)

- ✅ استخراج مبلغ، تاریخ و مرجع از تصویر به‌صورت «پیشنهاد» با تأیید کاربر
- ✅ تبدیل ویس فارسی به متن با نمایش و تأیید کاربر، سپس تطبیق اسامی با فهرست رسمی
- ✅ fallback بدون هزینه هنگام خطای 429/403/404/شبکه
- ✅ رضایت سازمان (`AI_CONSENT_CONFIRMED`) و رضایت تک‌تک کاربران
- ⚠️ **دقت واقعی روی فاکتورها و ویس‌های واقعی اندازه‌گیری نشده است.** درصد دقتی ادعا نمی‌شود.

### فاز C — تکمیلی

- ✅ گزارش ماهانه (شمسی) و بازهٔ دلخواه
- ✅ تجمیع پرداخت‌ها به تفکیک پرداخت‌کننده
- ✅ PDF روزانهٔ ادمین با پیوست مدارک: هر عکس فاکتور غذا و رسید پرداخت در یک صفحهٔ جدا با توضیح کارمند
- ✅ بایگانی خصوصی گزارش‌ها در Drive، Snapshot JSON و فرمان `/reports`
- ✅ هشدار تخمینی بودن مبلغ و درخواست‌های در انتظار هم‌زمان یک نفر، علامت تکرار مدرک و شماره سفارش
- ❌ داشبورد وب‌اپ (اختیاری در PRD؛ انجام نشد)

| مورد | چرا مشروط است | روش تأیید |

| رندر واقعی XLSX و PDF فارسی (فونت، صفحه‌بندی، اندازهٔ تصاویر پیوست) | Export گوگل در شبیه‌ساز اجرا نمی‌شود؛ فقط درخواست Export تست شده است. | `sendTestReport` و باز کردن فایل‌ها |
| رفتار واقعی LockService و سهمیه‌ها زیر بار | در شبیه‌ساز، قفل ترتیبی شبیه‌سازی شده است. | آزمایش با چند کاربر هم‌زمان |
| Gemini Free Tier | دسترسی منطقه‌ای (احتمالاً برای ایران پشتیبانی نمی‌شود)، نام مدل و سهمیه بررسی نشده‌اند. | راهنمای AI در README |
| دقت OCR و تشخیص ویس فارسی | بدون دادهٔ آزمون واقعی | ارزیابی با چند نمونه واقعی |
| زمان اجرای تریگر گزارش روزانه | تریگرهای گوگل دقیق نیستند (حدود یک ساعت). | مشاهده در Executions |

### ❌ انجام‌نشده (عمداً یا خارج از دامنه)

- پرداخت خودکار از طریق API بانکی. **عمداً انجام نشد.** «پرداخت‌شده» فقط با اقدام صریح ادمین ثبت می‌شود.
- حذف خودکار اسناد پس از دورهٔ نگهداری. عمداً فقط اطلاع‌رسانی می‌شود؛ حذف دستی و طبق سیاست سازمان است.
- اعتبارسنجی رمزنگاری‌شدهٔ هدر Webhook (در Apps Script ممکن نیست؛ گزینهٔ Cloudflare Worker در SECURITY.md آمده است).
- OCR یا Whisper آفلاین روی سیستم شخصی (به روشن ماندن دستگاه وابسته است).
- داشبورد وب.
- صف خودکار برای پردازش دوبارهٔ updateهای ناموفق. اگر پردازشی ناموفق باشد، کاربر پیام «خطای موقت» می‌گیرد و همان کار را تکرار می‌کند؛ داده‌های قبلی حفظ می‌شوند.
