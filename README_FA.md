# ربات رایگان مدیریت هزینه ناهار کارکنان (تلگرام)

ربات تلگرامی که درخواست بازپرداخت هزینه ناهار را مرحله‌به‌مرحله می‌گیرد، **فاکتور خرید و رسید پرداخت** را اجباری دریافت می‌کند، سقف روزانه هر نفر را درست حساب می‌کند، **کل مبلغ مجاز را به پرداخت‌کننده سفارش** منتسب می‌کند، تأیید ادمین مالی را می‌گیرد و گزارش **Excel و PDF فارسی** می‌سازد.

- **همه مبالغ به ریال** و عدد صحیح‌اند (ثبت، محاسبه، پیام‌ها و گزارش‌ها). سقف پیش‌فرض: **۳٬۵۰۰٬۰۰۰ ریال** برای هر نفر در هر روز.
- **هزینه صفر:** Telegram Bot API + Google Apps Script + Google Sheets + Google Drive. بدون سرور، دامنه، دیتابیس یا سرویس پولی. لپ‌تاپ شما لازم نیست روشن بماند.
- **هوش مصنوعی اختیاری و پیش‌فرض خاموش است.** همه امکانات بدون AI کار می‌کنند.

## معماری

```text
کارمند/ادمین در تلگرام
        │  (پیام، عکس، دکمه)
        ▼
Telegram Bot API ──Webhook──► Google Apps Script Web App (doPost)
                                 │  بررسی secret → حذف تکراری (update_id) → قفل → پردازش
                                 ├──► Google Sheets  (کارکنان، درخواست‌ها، سهم افراد، پرداخت‌ها، تاریخچه)
                                 ├──► Google Drive   (پوشه خصوصی مدارک و بایگانی گزارش‌ها)
                                 └──► Gemini API     (فقط اگر روشن شود؛ پیشنهادی و نیازمند تأیید)
```

| تصمیم | دلیل |
|---|---|
| Apps Script به‌عنوان سرور | رایگان، همیشه روشن، بدون نیاز به کارت بانکی |
| Google Sheets به‌عنوان پایگاه داده | رایگان و قابل مشاهده/ویرایش برای ادمین؛ همزمانی با `LockService` کنترل می‌شود |
| فرم مرحله‌ای (Wizard) | بدون AI هم کامل کار می‌کند؛ هر مرحله قابل بازگشت و اصلاح است |
| موتور مالی قطعی | AI هرگز مبلغ نهایی را تعیین نمی‌کند؛ محاسبه با کد و تأیید نهایی با ادمین است |
| Excel/PDF با Export رسمی گوگل | خروجی واقعی XLSX و PDF راست‌به‌چپ بدون کتابخانه پولی |

## پیش‌نیازها

همه رایگان:

1. یک حساب **Google** (Gmail یا Google Workspace).
2. یک حساب **Telegram** برای مالک ربات.
3. یک مرورگر کامپیوتر برای راه‌اندازی اولیه. بعد از نصب، کامپیوتر لازم نیست.

## نصب گام‌به‌گام

### گام ۱ — ساخت ربات در BotFather

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید و `/newbot` را بفرستید.
2. یک نام نمایشی (مثلاً «ربات هزینه ناهار») و یک username که با `bot` تمام شود (مثلاً `my_lunch_expense_bot`) بدهید.
3. BotFather یک **توکن** مثل `123456789:AA...` می‌دهد. این توکن رمز ربات است: آن را در جایی امن نگه دارید و به کسی ندهید.
4. **Privacy Mode** را خاموش نکنید (پیش‌فرض روشن است). ربات برای کار در چت خصوصی طراحی شده است.

### گام ۲ — گرفتن Telegram ID عددی خودتان (مالک)

- به ربات [@userinfobot](https://t.me/userinfobot) پیام بدهید و عدد `Id` را یادداشت کنید (مثلاً `111111111`).
- روش دیگر: بعد از نصب، به ربات خودتان `/start` بزنید؛ ربات شناسه شما را نشان می‌دهد.

> ⚠️ نقش‌ها فقط با این شناسه عددی تعیین می‌شوند، نه با username یا نام نمایشی.

### گام ۳ — ساخت Google Sheet و پروژه Apps Script

1. در [sheets.google.com](https://sheets.google.com) یک Spreadsheet خالی بسازید و نامش را مثلاً `LunchBot Database` بگذارید.
2. از منوی **Extensions → Apps Script** (افزونه‌ها ← Apps Script) ویرایشگر کد را باز کنید.
3. نام پروژه را (بالا سمت چپ) مثلاً `LunchBot` بگذارید.

### گام ۴ — قرار دادن کد

**روش الف (ساده، پیشنهادی): یک فایل**

1. در ویرایشگر Apps Script، محتوای فایل پیش‌فرض `Code.gs` را کامل پاک کنید.
2. کل محتوای فایل [`dist/LunchBot.gs`](dist/LunchBot.gs) این مخزن را کپی و در `Code.gs` جایگذاری کنید و ذخیره کنید (Ctrl+S).
3. از نوار کناری **Project Settings** (چرخ‌دنده ⚙️) گزینه **Show "appsscript.json" manifest file in editor** را تیک بزنید.
4. به **Editor** برگردید، فایل `appsscript.json` را باز کنید و محتوای آن را با [`dist/appsscript.json`](dist/appsscript.json) جایگزین و ذخیره کنید.

> اگر ویرایشگر به‌خاطر حجم فایل (حدود ۲۶۰ هزار کاراکتر) خطا داد، به‌جای یک فایل، هر فایل پوشه [`apps-script/`](apps-script) را جداگانه بسازید: کنار «Files» روی **+ → Script** بزنید، همان نام را بدهید (مثلاً `Wizard`) و محتوا را جایگذاری کنید. ترتیب فایل‌ها اهمیتی ندارد. یا از روش ب استفاده کنید.

**روش ب (برای برنامه‌نویس‌ها): چند فایل با clasp**

```bash
npm install -g @google/clasp
```

```bash
clasp login
```

فایل `.clasp.json.example` را با نام `.clasp.json` کپی کنید و `scriptId` پروژه را در آن بگذارید. این شناسه را در Project Settings → IDs پیدا می‌کنید. سپس:

```bash
clasp push
```

### گام ۵ — تنظیم رمزها در Script Properties

در **Project Settings ⚙️ → Script Properties → Add script property** این دو مورد را اضافه کنید:

| Property | مقدار |
|---|---|
| `BOT_TOKEN` | توکنی که از BotFather گرفتید |
| `OWNER_TELEGRAM_IDS` | Telegram ID عددی شما (برای چند مالک، با کاما جدا کنید) |

> این مقادیر را هرگز در شیت، کد یا پیام تلگرام قرار ندهید. نمونه کامل: [`config/script-properties.example`](config/script-properties.example)

### گام ۶ — اجرای `setup` و تأیید مجوزها

1. در نوار ابزار ویرایشگر، از فهرست توابع **`setup`** را انتخاب و **Run** را بزنید.
2. پنجره مجوز باز می‌شود: **Review permissions** ← حساب خود را انتخاب کنید.
3. اگر پیام «Google hasn't verified this app» آمد: **Advanced** ← **Go to LunchBot (unsafe)** ← **Allow**. این اسکریپت متعلق به خود شماست و فقط به Sheet و Drive و آدرس‌های تلگرام دسترسی می‌گیرد (فهرست مجوزها در `appsscript.json` آمده است).
4. در **Execution log** باید پیام‌های ✅ را ببینید: شیت‌ها ساخته شده‌اند، پوشه خصوصی Drive ساخته شده و اتصال به تلگرام برقرار است.

`setup` تکرارپذیر است. اگر دوباره اجرا شود، داده یا تنظیمات موجود را پاک نمی‌کند.

### گام ۷ — استقرار به‌عنوان Web App

1. بالا سمت راست، **Deploy → New deployment** را بزنید.
2. روی چرخ‌دنده کنار «Select type» بزنید و **Web app** را انتخاب کنید.
3. تنظیمات:
   - **Execute as:** `Me`
   - **Who has access:** `Anyone`
4. **Deploy** را بزنید و آدرس **Web app URL** را کپی کنید. این آدرس با `/exec` تمام می‌شود.
5. در **Script Properties** یک property جدید بسازید: `WEB_APP_URL` = همین آدرس.

> «Anyone» لازم است تا تلگرام بتواند پیام‌ها را تحویل دهد. امنیت با یک کلید محرمانه طولانی در آدرس Webhook و فهرست مجاز کارکنان تأمین می‌شود ([SECURITY.md](SECURITY.md)).

### گام ۸ — اتصال تلگرام (Webhook)

1. تابع **`setWebhook`** را اجرا کنید.
2. تابع **`checkWebhook`** را اجرا کنید. در Execution log باید `last_error: ندارد` و `pending_update_count: 0` دیده شود.

اگر خطای `302 Moved Temporarily` دیدید، به [رفع اشکال](#رفع-اشکال) بروید. یک حالت پشتیبان هم وجود دارد که بدون Webhook کار می‌کند.

### گام ۹ — اولین استفاده

1. در تلگرام به ربات خودتان `/start` بزنید.
2. چون مالک هستید، ربات نام و نام خانوادگی‌تان را می‌پرسد و پروفایل شما را با نقش «مالک ربات» می‌سازد.
3. منوی اصلی ظاهر می‌شود.

### گام ۱۰ — افزودن کارکنان و ادمین‌ها

**روش ۱ (پیشنهادی): درخواست عضویت.** هر کارمند به ربات `/start` می‌زند و نام کاملش را می‌فرستد. برای شما و ادمین‌های مالی پیامی با این دکمه‌ها می‌آید:

- **✅ تأیید به‌عنوان کارمند جدید**
- **🔗 اتصال به کارمند موجود در فهرست:** اگر نام او را قبلاً در شیت وارد کرده‌اید.
- **❌ رد**

**روش ۲: ورود دستی در شیت `Employees`.** هر ردیف یک کارمند است:

| ستون | توضیح |
|---|---|
| `employee_id` | یک شناسه یکتا، مثلاً `E-ALI001` |
| `full_name_fa` | نام کامل فارسی |
| `telegram_user_id` | شناسه عددی تلگرام. اگر خالی بماند، بعداً با «اتصال به کارمند موجود» پر می‌شود. |
| `aliases` | نام‌های مستعار با کاما (مثلاً `ممد، محمدجان`) برای تطبیق اسامی تایپ‌شده |
| `active` | `TRUE` یا `FALSE` |
| `role` | `employee` / `finance_admin` / `report_viewer` / `owner` |
| `department` | اختیاری؛ برای رفع ابهام نام‌های مشابه نمایش داده می‌شود |
| `payment_identifier_optional` | اختیاری (مثلاً شماره شبا)، فقط اگر سیاست سازمان اجازه می‌دهد |

**تعیین ادمین مالی:** مالک در تلگرام `/employees` را می‌زند، کارمند را انتخاب می‌کند و «نقش: ادمین مالی» را می‌زند. می‌توانید ستون `role` را در شیت هم مستقیم تغییر دهید.

### گام ۱۱ — آزمایش گزارش واقعی

تابع **`sendTestReport`** را اجرا کنید. یک فایل Excel و یک PDF برای مالک ارسال می‌شود. هر دو را باز کنید و مطمئن شوید متن فارسی و اعداد درست نمایش داده می‌شوند. همچنین تابع **`runSelfTests`** را اجرا کنید تا آزمون سریع موتور مالی و تبدیل ریال/تاریخ داخل Apps Script انجام شود.

### چک‌لیست پایان نصب

- [ ] `/start` در تلگرام پاسخ می‌دهد.
- [ ] یک درخواست آزمایشی با دو عکس (فاکتور و رسید) ثبت شد و کد پیگیری گرفت.
- [ ] ادمین کارت درخواست را دریافت کرد و «تأیید» کار کرد.
- [ ] «ثبت پرداخت‌شده» پیام واریز را برای کارمند فرستاد.
- [ ] `/dailyreport` فایل‌های Excel و PDF درست فرستاد.
- [ ] پوشه `LunchBot Data (Private)` در Drive با کسی Share نشده است.

## استفاده روزمره

### کارمند

1. **➕ ثبت هزینه ناهار** را بزنید.
2. روش خرید را انتخاب کنید (آنلاین/حضوری) و بعد روش پرداخت (بانکی/اعتباری/ترکیبی).
3. **عکس فاکتور یا اسکرین‌شات سفارش** را بفرستید و «ثبت مدرک خرید» را بزنید.
4. **عکس رسید پرداخت** را بفرستید و «ثبت مدرک پرداخت» را بزنید. عکس موجودی اعتبار کافی نیست.
5. تاریخ سفارش را انتخاب کنید (امروز/دیروز/تاریخ دیگر).
6. افراد را تایپ کنید (مثلاً «خودم، محمد و رضا») یا از فهرست انتخاب کنید.
7. مشخص کنید چه کسی پرداخت کرده است. **کل مبلغ مجاز به همین شخص پرداخت می‌شود.**
8. مبلغ نهایی فاکتور را **با واحد** بنویسید و اگر چند نفر بودید، بگویید سهم‌ها مساوی بوده یا جداگانه.
9. خلاصه را بررسی کنید و **✅ تأیید و ثبت** را بزنید. کد پیگیری می‌گیرید.

**ارسال آزاد:** می‌توانید همه جزئیات را در یک پیام بنویسید، مثلاً «امروز برای خودم، محمد و رضا از اسنپ‌فود غذا گرفتم. جمعش یک میلیون و دویست و شصت هزار تومان شد، خودم با کارت پرداخت کردم». ربات برداشت خودش را نشان می‌دهد و بعد از تأیید شما فرم را پیش‌پر می‌کند. مدارک همچنان اجباری‌اند.

### ادمین مالی

- با ثبت هر درخواست، **کارت بررسی** می‌رسد. کارت شامل سهم هر نفر، مصرف قبلی، ماندهٔ سقف، مبلغ مجاز و هشدارهاست، با این دکمه‌ها:
  `✅ تأیید` · `❌ رد` (با دلیل آماده یا دلخواه) · `✏️ درخواست اصلاح` · `📎 مشاهده مدارک` · `💰 اصلاح مبلغ` (با دلیل)
- لحظهٔ تأیید، سقف دوباره و با در نظر گرفتن همهٔ تأییدهای همان روز محاسبه می‌شود. اگر مبلغ تغییر کرده باشد، ربات مبلغ جدید را نشان می‌دهد و تأیید دوباره می‌خواهد.
- بعد از واریز، **💵 ثبت پرداخت‌شده** را بزنید (با شماره پیگیری یا بدون آن). پیش از پرداخت، **↩️ لغو تأیید** هم امکان‌پذیر است.

### فرمان‌ها

| کارمند | ادمین مالی / مالک | ناظر گزارش |
|---|---|---|
| `/new` ثبت هزینه | `/pending` در انتظار بررسی | `/dailyreport [تاریخ]` |
| `/myrequests` درخواست‌های من | `/unpaid` تأییدشده‌های پرداخت‌نشده | `/monthlyreport [۱۴۰۵/۰۸]` |
| `/status کد` وضعیت | `/review کد` کارت بررسی | `/export از تا` |
| `/balance` مانده سقف امروز | `/employees` کارکنان و عضویت‌ها | |
| `/cancel` لغو فرم جاری | `/settings` تنظیمات (`/set` فقط مالک) | |
| | `/reports` گزارش‌های بایگانی‌شده | |
| `/help` راهنما | همه فرمان‌های گزارش | |

نمونه گزارش بازه: `/export 1405/08/01 1405/08/15`

**گزارش خودکار:** هر روز حدود ساعت `REPORT_DAILY_HOUR` (پیش‌فرض ۱۷ به وقت تهران) برای ادمین‌های مالی و مالک ارسال می‌شود.

## واحد پول (ریال/تومان)

- **ذخیره، محاسبه، پیام‌ها و گزارش‌ها همه به ریال‌اند.** مثال: `۳٬۵۰۰٬۰۰۰ ریال`.
- اگر کارمند واحد را بنویسد (`۳۵۰ هزار تومان`، `3,500,000 ریال`)، ربات مستقیم تبدیل می‌کند: هر تومان برابر ۱۰ ریال.
- اگر واحد ننویسد (`350000`)، ربات **می‌پرسد**: `[ریال ← ۳۵۰٬۰۰۰ ریال]` یا `[تومان ← ۳٬۵۰۰٬۰۰۰ ریال]`. هیچ حدسی زده نمی‌شود.
- برای سهم تک‌تک افراد، اگر واحد ننویسند، همان واحدی که برای مبلغ کل انتخاب شده استفاده و در پیام تأیید نمایش داده می‌شود.
- مبلغ‌های غیرمعمول (کمتر از `LOW_AMOUNT_WARNING_RIAL` یا بیشتر از `HIGH_AMOUNT_WARNING_RIAL`) با هشدار، دوباره تأیید گرفته می‌شوند.
- ارقام فارسی، عربی و لاتین، جداکننده‌های `٬ , . ،` و عدد حروفی («یک میلیون و دویست هزار») پشتیبانی می‌شوند.

## تنظیمات

تنظیمات در شیت **`Settings`** هستند. مالک می‌تواند از تلگرام هم آن‌ها را تغییر دهد: `/set KEY VALUE`. تغییر در شیت حداکثر ظرف ۲ دقیقه اعمال می‌شود؛ برای اعمال فوری `clearSettingsCache` را اجرا کنید.

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `DAILY_CAP_RIAL` | `3500000` | سقف روزانه هر نفر (ریال) |
| `ALLOW_CREDIT_PAYMENTS` | `TRUE` | پذیرش پرداخت اعتباری (همیشه با تأیید ادمین) |
| `ALLOW_MIXED_PAYMENTS` | `TRUE` | پرداخت ترکیبی |
| `ALLOW_COMBINED_EVIDENCE` | `FALSE` | یک تصویر به‌جای هر دو مدرک (فقط با بررسی ادمین) |
| `ALLOW_EQUAL_SPLIT` | `TRUE` | سهم مساوی در سفارش گروهی |
| `ELIGIBLE_DELIVERY_FEE` / `ELIGIBLE_PACKAGING_FEE` / `ELIGIBLE_TAX` / `ELIGIBLE_TIP` | `TRUE` | هزینه‌های جانبی جزو مبلغ قابل بازپرداخت؛ اگر یکی را `FALSE` کنید، فرم مبلغ آن را می‌پرسد و کسر می‌کند |
| `MAX_CLAIM_AGE_DAYS` | `30` | حداکثر قدمت تاریخ سفارش |
| `LOW_AMOUNT_WARNING_RIAL` / `HIGH_AMOUNT_WARNING_RIAL` | `100000` / `200000000` | محدوده هشدار مبلغ |
| `MAX_FILE_MB` / `MAX_FILES_PER_STEP` | `20` / `10` | محدودیت فایل مدارک |
| `REPORT_DAILY_ENABLED` / `REPORT_DAILY_HOUR` | `TRUE` / `17` | گزارش خودکار |
| `REPORT_RECIPIENTS` | خالی | Telegram ID گیرندگان؛ خالی یعنی همه ادمین‌های مالی و مالک. افراد بدون نقش مجاز حذف می‌شوند. |
| `DRAFT_EXPIRY_DAYS` | `7` | لغو خودکار پیش‌نویس‌های رهاشده |
| `RETENTION_DAYS` | `1095` | دوره نگهداری؛ **حذف خودکار انجام نمی‌شود** و فقط اطلاع‌رسانی در AuditLog ثبت می‌شود |
| `AI_*`, `GEMINI_MODEL` | خاموش | بخش بعد |

**سقف تاریخ‌دار:** در شیت **`CapSchedule`** یک ردیف اضافه کنید: `effective_from_iso` (مثلاً `1405/09/01` یا `2026-11-22`) و `cap_rial` (مثلاً `4000000`). از آن تاریخ به بعد سقف جدید اعمال می‌شود و **تأییدهای گذشته تغییر نمی‌کنند**، چون سقف لحظهٔ تأیید در خود درخواست ذخیره می‌شود.

## روشن کردن هوش مصنوعی (اختیاری)

AI فقط **پیشنهاد** می‌دهد: مبلغ را از عکس فاکتور می‌خواند و ویس فارسی را به متن تبدیل می‌کند. کاربر باید پیشنهاد را تأیید کند، ادمین نهایی می‌کند و مبلغ همیشه با موتور مالی محاسبه می‌شود.

> ⚠️ پیش از روشن کردن حتماً بخوانید:
> - **دسترسی منطقه‌ای:** به احتمال زیاد ایران جزو [مناطق پشتیبانی‌شده Gemini API](https://ai.google.dev/gemini-api/docs/available-regions) نیست و استفاده از منطقه پشتیبانی‌نشده ممکن است خلاف شرایط سرویس باشد. وضعیت حساب و منطقه خود را بررسی کنید.
> - **حریم خصوصی:** در Free Tier ممکن است داده‌های ارسالی برای بهبود محصول گوگل استفاده شود. رسید بانکی و ویس کارکنان اطلاعات حساس‌اند؛ تأیید سازمان لازم است و هر کاربر هم جداگانه موافقت یا مخالفت می‌کند.
> - **هزینه:** **Billing را فعال نکنید.** اگر سهمیه رایگان تمام شود (خطای 429) یا دسترسی رد شود (403)، ربات خودکار به ورود دستی برمی‌گردد. هیچ هزینه یا ارتقایی انجام نمی‌شود.

مراحل:

1. در [Google AI Studio](https://aistudio.google.com/) یک API Key بسازید (بدون فعال‌سازی Billing).
2. در [صفحه قیمت‌ها](https://ai.google.dev/gemini-api/docs/pricing) و [محدودیت‌ها](https://ai.google.dev/gemini-api/docs/rate-limits) نام مدلی را پیدا کنید که **در Free Tier** ورودی تصویر و صوت را پشتیبانی می‌کند. نام مدل در کد هاردکد نشده است.
3. در Script Properties: `GEMINI_API_KEY` = کلید.
4. در شیت Settings (یا با `/set`):
   - `GEMINI_MODEL` = نام مدل
   - `AI_CONSENT_CONFIRMED` = `TRUE` (تأیید سازمان)
   - `AI_ENABLED` = `TRUE`
5. از این به بعد، هر کاربر در اولین `/new` یک بار موافقت یا مخالفت خود را اعلام می‌کند.

**خاموش کردن:** `/set AI_ENABLED FALSE`

## به‌روزرسانی کد

بعد از جایگزین کردن کد (روش الف یا `clasp push`):

1. **Deploy → Manage deployments** را باز کنید، روی ✏️ (Edit) بزنید و در **Version** گزینه **New version** را انتخاب کنید.
2. **Deploy** را بزنید. آدرس `/exec` **تغییر نمی‌کند** و لازم نیست Webhook را دوباره تنظیم کنید.
3. اگر ستون یا تنظیم جدیدی اضافه شده باشد، یک بار `setup` را اجرا کنید.

> اگر به‌جای Edit یک **New deployment** بسازید، آدرس عوض می‌شود. در آن صورت `WEB_APP_URL` را به‌روز و `setWebhook` را دوباره اجرا کنید.

## محدودیت‌های سرویس‌های رایگان

> این اعداد هنگام نگارش از مستندات رسمی گرفته شده‌اند و **ممکن است تغییر کنند**. پیش از استفاده، [صفحه سهمیه‌های Apps Script](https://developers.google.com/apps-script/guides/services/quotas) را بررسی کنید.

| مورد | حدود (حساب Gmail رایگان) | اثر در این ربات |
|---|---|---|
| زمان هر اجرای اسکریپت | ۶ دقیقه | پردازش هر پیام معمولاً ۱ تا ۵ ثانیه و گزارش ۱۰ تا ۶۰ ثانیه طول می‌کشد |
| فراخوانی‌های UrlFetch در روز | حدود ۲۰٬۰۰۰ | هر پیام ۲ تا ۵ فراخوانی دارد؛ برای ده‌ها کارمند کافی است |
| زمان کل تریگرها در روز | حدود ۹۰ دقیقه | گزارش روزانه و نگهداری چند دقیقه؛ حالت Polling بیشتر مصرف می‌کند |
| اجراهای هم‌زمان | حدود ۳۰ | پیام‌های هم‌زمان با قفل صف می‌شوند |
| ظرفیت Google Sheets | ۱۰ میلیون سلول در هر فایل | برای چند سال کار یک تیم کوچک کافی است؛ AuditLog قدیمی را سالانه بایگانی کنید |
| فضای Drive | سهم رایگان حساب گوگل (مشترک با Gmail) | عکس‌ها معمولاً ۱۰۰ تا ۵۰۰ کیلوبایت‌اند |
| دانلود فایل در Bot API تلگرام | ۲۰ مگابایت | فایل بزرگ‌تر با پیام مناسب رد می‌شود |

- **آپ‌تایم تضمین‌شده نیست.** Apps Script و Telegram سرویس رایگان‌اند و ممکن است گاهی کند یا قطع شوند. داده‌ها در Sheet می‌مانند.
- **Sheets دیتابیس تراکنشی نیست.** همزمانی با یک قفل سراسری کنترل می‌شود. برای تیم‌های کوچک تا متوسط (ده‌ها نفر) مناسب است.

## برای توسعه‌دهنده: تست‌ها و ساختار پروژه

```text
apps-script/        کد اصلی (هر ماژول یک فایل .gs) + appsscript.json
dist/               نسخه تک‌فایلی برای نصب ساده (npm run bundle)
tests/              شبیه‌ساز Apps Script/Telegram + تست‌های واحد و یکپارچه
scripts/            bundle.js (ساخت dist) و check-syntax.js
config/             نمونه Script Properties (بدون رمز واقعی)
docs/PLAN_FA.md     پلن ساخت و وضعیت دقیق هر قابلیت
SECURITY.md         امنیت، حریم خصوصی و محدودیت‌ها
```

اجرای تست‌ها (Node.js نسخه ۱۸ یا بالاتر، بدون نیاز به نصب بسته):

```bash
npm test
```

ساخت دوباره نسخه تک‌فایلی و تست همان نسخه:

```bash
npm run test:bundle
```

تست‌ها کد واقعی `.gs` را روی شبیه‌ساز درون‌حافظه‌ای Sheets، Drive، Lock، Cache و Telegram اجرا می‌کنند. همهٔ سناریوهای جدول PRD (به ریال)، همزمانی، idempotency، نقش‌ها، مرز نیمه‌شب تهران، خطای شبکه و AI را پوشش می‌دهند. **رندر واقعی XLSX/PDF توسط گوگل و رفتار واقعی تلگرام فقط با `sendTestReport` و چک‌لیست بالا در محیط واقعی تأیید می‌شود.**
